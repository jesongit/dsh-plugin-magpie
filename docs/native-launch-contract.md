# Native launch contract

Scope approved: desktop managed webview + one-time bootstrap + original Magpie POST sign-in. No expiry detection/relogin, no iframe fallback, no core or Magpie changes.

Important host fact: the DSH managed guest forbids network access to the DSH application host. It cannot load a /magpie/bootstrap URL on that listener, and must not receive the DSH browser cookie. Therefore bootstrap token issue/redeem stay on the parent application's existing authenticated owner RPC. A short-lived token is returned, consumed once over authenticated RPC, then an ephemeral sign-in descriptor is passed to the managed webview's native loadURL with POST body. The token and long-lived key NEVER occur in a URL. The descriptor exists briefly in trusted app renderer memory; never save it in client snapshot/store/localStorage/log/error. Browser/network context necessarily receives the management credential to POST, just as a normal form would. Magpie source remains original.

RPC additions:
- magpie.launch.issue {} -> {token:string, expiresAt:number}. 32-byte crypto random base64url, 30s TTL, bounded map, in-memory only. Captures management connection revision/identity; reconfiguration/disconnect/dispose invalidates old tokens. Consume before validation/return, concurrent second redemption fails.
- magpie.launch.redeem {token:string} -> {url:string, body:string}. url = normalized configured management base + /_magpie/sign-in; body = URLSearchParams({key:savedLoginKey,back:'/'}).toString(). No gateway key. Owner-only POST RPC, no-store. Error generic sanitized, never descriptor/secret.
- magpie.launch.revoke {token:string} -> {}. Idempotent explicit cleanup on cancellation. Drop all on disposal.

Backend owner module src/launch.ts: LaunchTickets({capture:()=>LaunchIdentity, now?}). LaunchIdentity server-only {url,loginKey,revision:number}; issue/redeem/revoke/dispose. MagpieService.launchIdentity() returns configured identity with dedicated connectionRevision incremented only on committed connect or disconnect (not refresh). Endpoint dispatch through existing connection.fetch owner guards; registerRpc owns lifecycle. Parent integrates registerRpc changes if agent doesn't own rpc.

Client MagpieClient.launchIssue(signal?), launchRedeem(token,signal?), launchRevoke(token): RPC calls directly, not snapshots. UI native controller acquires globalThis.dshDesktop.browser when protocolVersion===1, acquire(storageKey) -> {lease,partition}; creates webview name=lease partition=partition src=about:blank#lease (same approved sequence as native Sidebar Browser). First blank dom-ready loads the exact configured management root via a keyless GET (401 login page or 200 existing session allowed). Its dom-ready must match exact configured origin/path before issue/redeem. Do not GET /_magpie/sign-in as bootstrap: Magpie returns 404 on that static path when its cookie is already valid. Then execute only a fixed one-shot login IIFE which rechecks location internally and fetches the exact sign-in URL with method POST, credentials same-origin and redirect manual. JSON.stringify descriptor values, never concatenate unescaped user data. Returns only a boolean for opaqueredirect/303; no remote body or error. Native loadURL then GETs the clean configured management root and waits for main 200/DOM completion. This is a narrow startup-script exception, not remote DOM automation or rewriting Magpie assets. No native navigation POST: Chromium 307/308 would forward its body cross-origin before a did-navigate observer could reject it. Clears refs after the call; never log descriptor/script. No webview nodeIntegration/preload/custom unsafe flags. Release lease on unmount/cancel/errors and reject stale async operations. Unique storageKey for Magpie connection (not workspace; never same key as ordinary Browser). Fixed size no browser chrome. No network/proxy URL rewrite. No auto retries/relogin; explicit reload button may restart a new guest+POST.

Web/non-desktop: show clear native desktop requirement; do not silently use iframe or external browser. External open remains an explicit action, not normal launch. Preserve URL/key configuration gate, icon/settings/dock.
